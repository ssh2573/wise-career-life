# 슬기로운 이직생활

산업안전·안전보건 직무의 새 채용공고를 수집하고, 사용자별 조건에 맞는 공고를 Web Push로 알리는 웹앱입니다. OpenAI API, AI 에이전트, 유료 AI 키를 사용하지 않습니다.

## 현재 상태

- 서버·수집기·웹페이지·알림 구독/해제·전송 대기열을 구현했습니다.
- 자동 수집 대상은 잡코리아의 공개 검색·공고·기업정보입니다. 기존 온라인팜 공식 공고 등은 검증된 초기 자료로 유지되며, 해당 공식 사이트의 자동 수집기는 아직 없습니다.
- 실제 외부 수집 요청은 이 개발 환경에서 연결 시간 초과가 발생했습니다. 수집 성공을 확인한 것으로 표시하지 않습니다. 파서 테스트는 공개 페이지에서 확인한 항목 구조를 반영한 작은 테스트 자료로 실행했습니다.
- 알림 암호화는 RFC 8291의 공개 검증값과 일치합니다. 실제 휴대폰·브라우저의 Push 서비스 수신은 아직 검증하지 못했습니다.
- 소스 저장소: [ssh2573/wise-career-life](https://github.com/ssh2573/wise-career-life). 공개 서버 배포와 실제 수집·알림 수신 검증은 별도로 진행합니다.

## 실행

Node.js 24.5 이상이 필요합니다. 별도 패키지 설치 없이 실행합니다.

```sh
npm start
```

`http://127.0.0.1:4173`에서 열립니다. 서버를 켜 두는 동안 기본 1시간 간격으로 수집합니다. `.env.example`을 참고해 설정하며, 환경 파일을 사용할 때는 다음처럼 실행합니다.

```sh
node --env-file=.env --use-env-proxy server.mjs
```

브라우저에서 **알림 설정 → 새 공고 알림 → 권한 허용 → 설정 저장 → 테스트 알림** 순서로 확인합니다. 페이지를 닫아도 서버가 가동 중이고 기기의 알림 환경이 지원되면 Web Push가 동작합니다. 일부 앱 내 브라우저는 알림을 지원하지 않습니다. iPhone/iPad는 지원되는 Safari에서 홈 화면에 추가한 웹앱을 사용합니다.

## 수집과 알림 기준

- 목록과 알림에 동일한 필수 기준을 적용합니다: **직원 100명 이상 또는 연매출 100억원 이상**. 규모 수치를 확인하지 못한 기업은 제외합니다. 상장 여부·기업 유형은 별도 조건입니다.
- 안전보건, 산업안전, 안전관리자, EHS 키워드의 검색 결과를 제한된 요청 수 안에서 수집합니다. 전체 채용사이트를 모두 수집하는 서비스가 아니며, 검색 노출 한도 때문에 누락될 수 있습니다.
- 공고 ID로 중복을 제거합니다. 첫 번째 성공 수집은 기준 자료로 삼고, 그 이후 처음 발견한 공고만 알립니다. 재시작해도 이 기준을 유지합니다.
- 날짜가 지난 공고와 확인된 조기 마감 공고를 제외합니다. 사이트 접근 실패를 마감으로 처리하지 않습니다. 마지막 성공 시각·오류를 화면에 구분합니다.
- 알림 묶음 주기는 1시간·3시간·하루 중 선택합니다. 첫 새 공고는 다음 수집 시 보내고, 후속 알림은 마지막 발송 시각을 기준으로 묶습니다.
- ‘연차·자격증 기준 부합 공고만’을 켜면 세부 자격이 확인되지 않은 공고는 알리지 않습니다. 자동 수집한 새 공고의 이미지·첨부 자격을 추정하지 않기 때문에 이 옵션의 기본값은 꺼짐입니다. 기존 브라우저에 저장한 선택은 유지합니다.
- 복지·연봉·로고·규모에 없는 정보를 생성하지 않습니다. 새로 수집한 공고의 미확인 정보는 원문 확인으로 표시합니다. 기존 자료의 출처와 기준일은 유지합니다.
- 알림 서비스의 일시 오류는 간격을 늘려 재시도하고, 만료된 구독(404/410)은 제거합니다. 서버 전송 성공은 기기의 실제 표시를 보증하지 않으므로 테스트 알림을 확인합니다.

## 공개 서버 배포

이 버전은 서버가 계속 실행돼야 합니다. **GitHub Pages에 HTML만 올리면 자동 수집·알림이 실행되지 않습니다.** GitHub에는 소스를 저장하고, Node.js 또는 Docker를 지원하는 상시 서버에 배포합니다.

### Railway

1. GitHub 저장소를 서비스에 연결하고 포함된 `Dockerfile`로 배포합니다.
2. 영구 볼륨을 `/app/.runtime`에 연결합니다. 처음 시작할 때 이 폴더의 소유권을 준비한 뒤 일반 사용자로 서버를 실행합니다.
3. Networking에서 공개 도메인을 생성합니다. `RAILWAY_PUBLIC_DOMAIN`이 HTTPS 주소로 자동 적용됩니다. 자체 도메인은 `PUBLIC_ORIGIN`에 정확한 주소를 지정합니다.
4. Healthcheck Path는 `/healthz`, 복제본은 1개로 설정하고 서버 절전 기능은 끕니다. `RAILWAY_DEPLOYMENT_DRAINING_SECONDS=30`으로 종료 대기 시간을 설정합니다.
5. 웹페이지와 `/api/feed`를 열어 실제 수집 상태를 확인하고 테스트 알림을 수신합니다. 무료 체험 만료·비용 한도 도달 시 서비스가 중지될 수 있습니다.

참고: [Railway 볼륨](https://docs.railway.com/volumes), [상태 확인](https://docs.railway.com/deployments/healthchecks), [환경 변수](https://docs.railway.com/variables/reference).

### 일반 Docker 서버

1. `PUBLIC_ORIGIN`을 실제 HTTPS 웹주소로, `HOST`를 `0.0.0.0`으로 설정합니다.
2. `DATA_DIR`에 영구 저장공간을 연결합니다. 서버 재시작·배포 때 삭제되면 공고 기록과 알림 구독이 사라집니다.
3. 서버 프로세스는 한 개만 운영합니다. 여러 인스턴스를 쓰려면 공유 DB 및 작업 잠금으로 변경해야 합니다.
4. 운영자 연락처가 있으면 `VAPID_SUBJECT`에 실제 `mailto:` 주소 또는 HTTPS 연락처 페이지를 지정합니다. 생략하면 `PUBLIC_ORIGIN`을 사용합니다.
5. `/api/feed`에서 실제 수집 성공을 확인하고 브라우저의 테스트 알림을 수신한 뒤 상시 운영을 시작합니다.

```sh
docker build -t wise-career .
docker run --name wise-career --restart unless-stopped \
  -p 4173:4173 \
  -e PUBLIC_ORIGIN=https://your-real-domain.example \
  -v wise-career-data:/app/.runtime \
  wise-career
```

도메인은 실제 소유한 주소로 교체하고 앞단에 HTTPS를 제공하는 호스팅/리버스 프록시를 둡니다. 원래 Host 헤더가 보존되어야 합니다. 호스팅·도메인·데이터 서비스 비용은 AI 사용량과 별개입니다.

`.runtime/`에는 알림 키와 구독 정보가 들어갑니다. Git 저장소·정적 파일 경로·공유 압축파일에 포함하지 않습니다. 서버는 명시한 공개 파일만 제공합니다. HTTPS 알림 제공업체 주소만 허용하고 구독 변경에는 브라우저별 토큰을 확인합니다.

## 검증과 운영

```sh
npm test
# 실행 중인 서버를 중지한 상태에서 수집 1회 확인:
npm run collect
```

공유 정책, 첫 수집/새 공고/중복 제거, 마감 제외, 오류 보존, 재시도, 수집 파싱, 암호화 표준값, API 접근 제어를 검증합니다. 테스트용 공고나 알림 대상은 실제 데이터에 섞이지 않습니다.

수집 사이트의 `robots.txt`를 확인하고 제한된 경로는 요청하지 않습니다. 인증·접근 제한·CAPTCHA는 우회하지 않습니다. 사이트가 구조를 바꾸거나 수집 정책을 변경하면 수집기를 조정하거나 제공되는 공식 데이터 연동으로 교체해야 합니다.

참고: [Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API), [RFC 8291](https://www.rfc-editor.org/rfc/rfc8291), [RFC 8292](https://www.rfc-editor.org/rfc/rfc8292).
